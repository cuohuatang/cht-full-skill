# /cht-ship — 发布

## 门禁（缺一项不许发）

```
□ 全量测试绿（贴命令与输出）
□ 覆盖率未下降（下降有解释并获准）
□ 门禁完整性：无弱化断言/跳过测试/放宽超时
□ P0/P1 评审问题清零
□ QA 报告无未关闭 P0/P1
□ 迁移可回滚，且演练过 down
□ 新增配置已在部署平台配好（不是只写 .env.example）
□ 锁文件已提交
□ 文档同步：README / API / CHANGELOG
□ 变更说明：改了什么、影响谁、怎么验证
□ 回滚方案：一条命令 + 预期耗时 + 数据影响
□ 关键路径有指标与告警
□ 发布窗口确认（避开高峰与他人发布）
```

## 顺序（不可颠倒）

```
同步主干 → 冲突解决 → 本地全量 → 推分支 → CI 绿 → 评审
→ 合并 → 预发冒烟 → 生产灰度 → 观察 5–15 分钟 → 全量
→ 写发布记录
```

**不要同时做"合并 + 迁移 + 改配置"。**

## 观察阈值（发布前就写好）

错误率 >2x 基线 → 回滚；P95 延迟 >+50% → 回滚；关键业务指标下降 → 回滚；新错误类型占请求 >1% → 回滚。
**观察期倾向回滚**：回滚 2 分钟，带问题排查 2 小时。

## PR 描述五段

做了什么 / 为什么（链 SPEC）/ 怎么验证 / 影响面（用户、接口、数据）/ 回滚方式 / 门禁变化。

## 禁止

- 把 CI 绿当验证完成
- 发布完不看指标，直接宣布成功
- 不可逆变更（删列、改主键、发外部通知）单人操作
