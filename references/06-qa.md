# 06 · QA 与完成前验证（Test）

> QA 不是"再点几下看看"。QA 是**在真实环境里，用真实路径，找能被重放的证据**。
> 验证不是"跑一下测试"。验证是**在说出口之前，跑一遍能证伪这句话的命令**。

---

## 1. 完成前验证门（Iron Gate）

在说出任何"完成 / 修好了 / 通过了 / 部署成功"之前，执行这四步：

```
1. 识别：哪条命令能证明这句话？
2. 执行：完整跑一遍（新鲜的，不用昨天的输出）
3. 阅读：读完输出，看退出码，数失败数
4. 对照：输出真的支持这句话吗？
```

不满足就**不许说**。可以说"我改了 X，还没验证"，那是诚实的。

### 禁止的措辞（除非刚刚跑过并把输出贴出来）

- "应该可以了" / "理论上没问题"
- "测试都过了"（而实际只跑了新增的那一个）
- "已修复"（而实际只是改了代码）
- "部署成功"（而实际只是 push 了）
- "这个应该不影响其他功能"

### 输出模板

```
验证：<命令>
结果：<退出码 0>，<42 passed / 0 failed>，<耗时 3.2s>
说明：<这条命令覆盖了什么，没覆盖什么>
```

漏了"没覆盖什么"，验证就不完整——**边界声明比结论更重要**。

## 2. QA 环境矩阵

按被测对象选路径，不要总是用网页那一套：

| 被测物 | 怎么测 | 证据形态 |
|---|---|---|
| Web 页面 | 真实浏览器，走关键用户路径（不只首页） | 截图 + 控制台日志 + 网络请求 |
| HTTP API | 真实请求：正常、缺参、越权、超限、幂等重放 | 状态码 + 响应体 + 服务端日志 |
| CLI | 真实终端跑：正常、无参、错参、缺文件、Ctrl-C | 退出码 + stderr |
| 定时任务 / Worker | 手动触发一次 + 模拟失败 + 重入 | 任务日志 + 数据落库结果 |
| Webhook | 真实投递 + 重放 + 签名错误 | 请求记录 + 处理结果 |
| 数据库迁移 | 在快照库上跑 up + down + 再 up | 执行输出 + 表结构 diff |

**绝不用 mock 当 QA。** mock 测的是你的假设，QA 测的是现实。

## 3. QA 循环：复现 → 回归 → 修因 → 复验

```
1. 复现：稳定复现，写下最短操作序列
2. 记录：截图 / 请求 / 日志，能给别人重放的证据
3. 回归测试：把它写成一条自动化测试，跑 → 必须 RED
4. 修根因（不是症状，见 references/04-debugging.md）
5. 复验：原始序列再走一遍 + 全量测试
6. 同类扫描：这个模式在别处有没有
```

每一步都要落进 `QA-REPORT.md`，格式：

```
BUG-1 [P1] 上传 45 分钟音频后行动项为空
  复现：上传 fixtures/45min.m4a → 等待 → 列表为空，控制台无错误
  证据：screenshot-01.png / 服务端日志 14:22:03 处 asr timeout 30s
  根因：ASR 超时设置为 30s，长音频必超；超时后返回空数组而非错误
  修复：超时改按音频时长动态计算 + 超时抛 AsrTimeout 而非空数组
  回归：tests/ingest/long-audio.spec.ts
  复验：原文件重传 → 12 条行动项，耗时 47s ✓
```

## 4. 探索式测试：找 AI 想不到的坑

固定路径能过不代表没问题。以下场景逐个走：

**输入侧**
- 空 / 只有一个字符 / 超长（10 倍正常量）/ 全 emoji / 中文标点 / 混合语言
- 特殊字符：`'` `"` `<script>` `../` `%00` `\n` 
- 重复提交（双击、刷新重发）
- 并发：两个标签页同时操作同一资源

**状态侧**
- 直接访问深链接（未登录、无权限、资源不存在）
- 浏览器后退 / 刷新 / 中途关闭
- 网络慢（限速到 3G）/ 断网 / 请求超时
- 数据为空（新用户第一次进来）
- 数据极多（1000 条列表）

**权限侧**
- 普通用户访问管理员端点
- A 用户用自己的 token 请求 B 用户的资源 id
- 过期 token / 撤销后的 token

**恢复侧**
- 失败后重试能成功吗？
- 中断后数据是否半截？能续吗？
- 回滚后旧数据还能读吗？

## 5. 上线前冒烟（发布前 10 分钟）

```
□ 健康检查端点返回 200 且含版本号
□ 核心路径走一遍：注册/登录 → 主功能 → 退出
□ 一条真实数据写入并读回
□ 日志能看到这次请求的 trace id
□ 错误上报平台没有任何新错误
□ 静态资源无 404（打开控制台看）
□ 关键页面在移动端宽度下不破版
```

冒烟不通过**不许发**。
