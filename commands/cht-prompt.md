# /cht-prompt · 提示词优化前置闸门

**先分流，再优化。** 绝大多数输入根本不该被优化——这是本命令存在的首要理由。

## 四种调用形态

| 调用 | 行为 |
|---|---|
| `/cht-prompt <原始输入>` | 走闸门 → 该优化则给**双版本**，不该优化则**原样透传** |
| `/cht-prompt --check <原始输入>` | **只判断**要不要优化，输出裁决与命中规则，不产出任何提示词 |
| `/cht-prompt --lite <原始输入>` | 只要精简通用版 |
| `/cht-prompt --full <原始输入>` | 只要高阶顶配版 |

`--check` 对应"只要判断不要优化"这一类请求，但**即使用户没加 `--check`，只要他说了「只判断」「别改」「原样」，也一律按透传处理**。

## 执行流程

```
1. 跑闸门   bash scripts/prompt_gate.sh --why "<原始输入>"
2. 看裁决
   ├─ PASS_THROUGH / AMBIGUOUS → 原样输出用户输入，结束（零改写、零解释）
   └─ OPTIMIZE                → 进入 3
3. 四步优化（见 references/25-prompt-architect.md §4）
   补齐隐性需求 → 出双版本 → 结构化排版 → 全 Agent 适配自检
4. 过 §6 的 10 条自检 + §8 红牌，不过就重写
```

闸门只是确定性预检，**最终裁决由宿主结合上下文做出**。脚本判 `AMBIGUOUS` 时按透传处理，不要硬凑一个优化版本出来。

## 输出模板（仅 OPTIMIZE 时）

````markdown
## 精简通用版
（一段可直接复制进任何聊天框的完整提示词；含角色、任务、输出格式、关键约束；
  不写路径 / 命令 / skill 名 / @引用 / 会话指代）

## 高阶顶配版
（完整可独立使用的提示词：上下文与输入材料 → 分步骤 → 验收标准 →
  边界与非目标 → 失败降级 → 反例 → 自检清单；
  cht 专属语法须单独标注，通用能力须带"若环境不支持 X 则改为 Y"）
````

两版之外**不写任何其他内容**：不加开场白、不加"我补了什么"的说明、不加对比表、不加使用建议、不加寒暄。用户要的是能复制走的东西。

## 透传时的行为（硬约束）

`PASS_THROUGH` / `AMBIGUOUS` 时，输出**就是用户那句原话**，一个字不改、不附加任何说明。

连「此输入无需优化」都不写。理由：用户要的是执行，不是听你把判断过程汇报一遍——那恰好是这套方法论要求砍掉的废话。

## 裁决速查

| 输入 | 裁决 |
|---|---|
| 你好 / 谢谢 / 收到 | 透传 |
| 什么是 TCP 三次握手？/ 把这段翻译成英文 / 缩成 100 字 | 透传 |
| 继续 / 换成蓝色 / 把标题改成 24px | 透传 |
| 用 `/cht-audit` 审一下 / 打开 `SKILL.md` | 透传 |
| 只判断要不要优化 / 对不对？ | 透传 |
| 帮我安装并配置好 PostgreSQL | **优化** |
| 生成一份季度销售分析报告 / 归纳总结并给方案 | **优化** |
| 修复 / 转换 / 推送 / 重构 / 产出文件 | **优化** |
| 把 CSV **转换成** JSON（不是「换成」） | **优化** |
| 嗯 / 看看（灰区） | 透传 |

## 红牌

- 改写禁止优化的输入，或在透传时加解释性旁白
- 「只判断」请求下仍产出双版本
- 借「补齐隐性需求」擅自加功能、扩范围、替用户做决定
- 丢掉原话里的数字 / 路径 / 报错串 / 否定词
- 精简通用版里出现 `/cht-*`、文件路径、shell 命令、skill 名
- 给无 shell / 无文件系统的宿主塞命令，且不给降级路径
- 写出「尽量 / 适当 / 合理」等无法验收的软约束，或自相矛盾的指令
- 提示词里出现会话依赖指代（上文 / 刚才 / 按之前的）
- 拿"提示词已优化"冒充任务完成的验证证据
