# /cht-build — 执行计划

前置：`docs/cht/PLAN.md` 已批准。

## 执行

1. **选模式**：
   - 任务独立、可并行 → 子代理驱动（每任务一份简报 + 一次任务评审）
   - 任务强耦合 / 无子代理 / 用户要求省成本 → 内联（`references/03-execution.md §2`）
2. **逐任务 TDD**：
   ```
   RED   写测试 → 跑 → 亲眼看它失败，且失败在断言上
   GREEN 最小实现 → 跑 → 通过
   REFACTOR 清理 → 跑 → 仍通过
   COMMIT 一次提交
   ```
   测试一次就过 → 注释实现确认变红，否则是恒真测试。
3. **记 ledger**（`docs/cht/LEDGER.md`）：每条一行，类型 `RED/GREEN/RULING/BLOCKED/DEBUG`。
4. **连续执行**：不在任务之间问"要继续吗"。只在四种情况停：不可逆操作 / 安全敏感 / 工作区外副作用 / 计划已崩。
5. **裁决不停摆**：`Ruling: 决定了什么 — 为什么 — 错了的代价`，写进 ledger 后继续。
6. **计划错了**：局部细节直接改并记录；任务拆分错就改 PLAN；根本假设错 → 停下回 `/cht-plan`。

## 禁止

- 一次改十个文件而不跑测试
- 留着 `TODO` 占位就交付
- 提交密钥、调试输出、注释掉的旧代码
- `--no-verify` 跳过钩子

## 完成判据

- [ ] 全部任务完成，ledger 有对应 RED + GREEN
- [ ] 全量测试通过（贴输出）
- [ ] 提交历史一次任务一次提交
- [ ] 所有裁决已记录
- [ ] 自己先按 `references/06-qa.md §1` 验证过
