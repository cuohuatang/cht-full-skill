# /cht-debug — 系统化调试

## 铁律

```
没有完成根因调查，不许提出修复。
```

没有假设就改代码 = 随机搜索。不接受"这个很明显"。

## 执行

**阶段 1 · 复现与定位**
1. 稳定复现（给一条命令，每次都同样失败）。不能稳定就先解决"为什么不能稳定"。
2. 二分缩小：注释一半 / 换输入 / 换环境 / `git bisect`。
3. 读错误**全文**：栈顶、`caused by`、退出码、前后 20 行日志。
4. 对照近期变更：`git log --oneline -20`、`git diff` 上次绿灯以来。
5. 写出可证伪假设：
   ```
   根因假设：<哪里> 在 <什么条件> 下 <做了什么错事>，因为 <机制>
   证据：<跑过的命令 + 输出>
   ```
   写不出 → 还在阶段 1。

**阶段 2 · 假设检验**
一次验证一个假设。优先最便宜的实验（log / 5 行复现脚本 / REPL）。实验必须有预期结果。

**阶段 3 · 修复**
- 修根因，不是症状（`try/catch` 吞异常、加 `?? fallback`、调大超时都是症状修复）
- 先写会失败的回归测试，再修，修完必须变绿
- 修完全量测试 + 检查同类位置

**阶段 4 · 复验与记录**
原始复现步骤再跑；贴证据；记 ledger `[DEBUG] 根因/修复/回归/同类检查`。

## 三次失败就停

同一问题连续 3 次修复失败 → 停止改代码：
列出已排除的假设 → 列最强假设与缺失证据 → 派新上下文代理复看 → 要用户提供环境信息 → 考虑止血降级（明确标为技术债）。

## 输出

```
根因：<一句话>
证据：<命令 + 关键输出>
修复：<文件:行> <改法>
回归：<测试文件::用例名>（曾 RED，现 GREEN）
未覆盖：<这次没查的范围>
```
