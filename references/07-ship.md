# 07 · 发布（Ship）

> 发布工程师只关心一件别人不关心的事：**出事怎么退回来。**
> 没有回滚路径的发布，不是发布，是赌博。

---

## 1. 发布门禁（逐项打勾，缺一项不许发）

```
□ 全量测试绿（贴命令与输出，不是"跑过了"）
□ 覆盖率没有下降（或下降有解释并获准）
□ 门禁完整性：没有弱化断言、跳过测试、放宽超时（见 references/05-review.md §2.5）
□ P0/P1 评审问题清零
□ QA 报告里没有未关闭的 P0/P1
□ 数据库迁移可回滚，且已在快照库演练过 down
□ 配置项已加（新增环境变量在部署平台配好，不是只写在 .env.example）
□ 依赖已锁定，锁文件已提交
□ 文档同步：README / API 文档 / CHANGELOG
□ 变更说明写清：改了什么、影响谁、怎么验证
□ 回滚方案写完：一条命令 + 预计耗时 + 数据影响
□ 监控与告警：本次新增的关键路径有指标吗
□ 发布窗口确认（避开用户高峰、避开其他人正在发布）
```

---

## 2. PR 描述标准

```
## 做了什么
<一句话 + 3 条要点>

## 为什么
<链接到 SPEC / issue>

## 怎么验证
<命令 + 预期输出；手动路径>

## 影响面
- 用户可见变化：<有/无，是什么>
- 接口变化：<有/无，是否破坏兼容>
- 数据变化：<有/无，是否需要迁移>

## 回滚
<git revert <sha> / 关闭开关 / 执行 down 迁移>

## 门禁变化
<无 / 本次调整了 X，原因 Y，恢复时间 Z>
```

PR 描述里的每一句都必须是**可核查的事实**，不是"已充分测试"。

---

## 3. 发布顺序（不可颠倒）

```
1. 同步主干 → 解决冲突 → 本地全量测试
2. 推送分支 → CI 绿 → 再请评审
3. 合并（squash 或 merge，按仓库惯例）
4. 部署到预发 → 冒烟（references/06-qa.md §5）
5. 部署到生产（灰度 / 小流量）
6. 观察 5–15 分钟：错误率、延迟、关键业务指标
7. 全量放量
8. 记录发布日志（版本、时间、变更、观察结果）
```

**不要在同一个时间做"合并 + 迁移 + 配置变更"三件事。** 出问题时你不知道是哪一件。

---

## 4. 回滚准备

发布前必须能回答：

| 问题 | 答案要求 |
|---|---|
| 代码怎么退？ | `git revert <sha>` 还是 redeploy 上一个 tag？多久生效？ |
| 数据能退吗？ | 迁移有没有 down？不可逆的数据变更（删列、改类型）有没有备份？ |
| 有开关吗？ | 新功能是否在 feature flag 后面？关掉会不会影响老数据？ |
| 退回去之后，已经写进去的新格式数据怎么办？ | 向下兼容策略 |
| 谁来退？ | 有没有人知道怎么退（不只是你） |

不可逆的发布（删数据、改主键、发外部通知）需要**双人确认**。

---

## 5. 发布后观察（金丝雀）

前 15 分钟盯这四个：

```
错误率     比基线高 >2x → 回滚
P95 延迟   比基线高 >50% → 回滚
关键业务指标（下单/上传/登录成功率）下降 → 回滚
日志里出现新错误类型 → 看量级，>1% 请求 → 回滚
```

判断标准**发布前就写好**，不要在慌乱中临时定阈值。

观察期内的原则：**倾向回滚。** 回滚是 2 分钟的事，线上带着问题排查是 2 小时的事。修好再发一次成本很低。

---

## 6. 变更说明（给用户看的）

不是 git log 的复制。三类读者，三种写法：

| 读者 | 关心 | 写法 |
|---|---|---|
| 终端用户 | 我能多做什么 / 什么变了 | "现在可以直接把会议录音拖进来，自动生成行动项" |
| 开发者（API/SDK） | 我的代码会不会挂 | "`POST /v1/items` 返回值新增 `source` 字段，向后兼容；`GET /v1/items` 分页默认值从 50 改 20" |
| 运维/值班 | 出问题先看哪 | "新增依赖 ASR 服务，超时 60s，失败会进 dead 队列，看 `/admin/dead`" |

版本号规则（语义化）：

- **patch** 0.0.x：修 bug，无接口变化
- **minor** 0.x.0：加功能，向后兼容
- **major** x.0.0：破坏兼容

本仓库当前 `V0.0.1`。

## 7. 发布后要留下的东西

```
docs/cht/RELEASES.md 追加一条：
## v0.0.1 — 2026-10-29
变更：<3 条>
验证：<测试数、QA 结论>
观察：<15 分钟内的指标>
回滚记录：<无 / 回滚过一次，原因 …>
遗留：<已知未做的事，和技术债编号>
```
