# 11 · 用 TDD 写 Skill（Writing Skills）

> **写 skill 就是 TDD 用在了流程文档上。**
> 你没看见过 agent 在没有这个 skill 时失败，你就不知道这个 skill 教对了东西。

---

## 1. 什么该写成 skill

| 该 | 不该 |
|---|---|
| 可复用的技术、模式、判断标准 | 「我某次怎么解决某个 bug」的叙事 |
| 每次都需要同样纪律的流程 | 一次性的操作记录 |
| 有明确触发条件的领域知识 | 泛泛的「要重视质量」 |

判据：**下次遇到同类任务，agent 会因为读了它而做出不同选择吗？** 不会，就不该写。

---

## 2. TDD 映射

| TDD | 写 skill |
|---|---|
| 写一个失败的测试 | 构造压力场景：让 agent 在没有 skill 时处理这个任务 |
| 看它失败 | 观察基线行为（它会跳过验证、会猜着改、会一次改十个文件） |
| 写最小实现 | 写 skill，只针对观察到的失败 |
| 看它通过 | 同一场景重跑，agent 行为改变了 |
| 重构 | 堵漏洞：找出它绕过的理由，把漏洞写死 |

**关键**：基线必须真的跑。凭想象写出的 skill，90% 在解决不存在的问题。

---

## 3. 结构规范

```markdown
---
name: <kebab-case，与目录名严格一致>
description: <何时使用 + 做什么 + 触发词。第三人称，含具体场景词>
version: "x.y.z"
---

# 标题

> 一句话核心原则

## 何时使用 / 何时不用
## 核心流程（编号步骤）
## 判据与阈值（数字，不要形容词）
## 反模式清单
## 完成定义（可勾选）
```

硬性要求：

1. `name` 必须等于目录名。安装脚本与校验都依赖这一点。
2. `description` 决定**是否被加载**，比正文更重要。要包含：做什么、什么时候用、用户可能说的原话。
3. 正文用**命令式**，写给执行者看，不写给读者欣赏。
4. 有数字就写数字（"任务 30–120 行"优于"任务不要太大"）。
5. 一个 skill 只解决一类问题。装了两类就该拆。

---

## 4. 防臃肿五阶梯（改 skill 时按顺序试）

改 skill 时，从最低成本的手段开始，能解决就停：

```
1. 先修工具/脚本 —— 能不能让工具直接做对，而不是写文档提醒别做错？
2. 不加模型已经会的东西 —— "要认真读代码"这种话，删掉
3. 改那一行，而不是追加一段 —— 追加会让文件无限膨胀
4. 用最低层级的手段 —— 能在 checklist 里解决，就不要写一整节
5. 写规则，不写故事 —— "必须 X" 优于 "有一次我们因为没 X 出了事"
```

检查手段：

- **体积**：单个 SKILL.md 建议 < 8KB。超过就开始分层（`references/`）。
- **漂移**：skill 里提到的命令、路径、参数，**现在还存在吗**？逐条验证。过时的引用比没有更糟。
- **无效声明**：删掉一句，agent 行为会变吗？不会，那句就是噪音。

---

## 5. 验证（不可跳过）

写完必须做三件事：

1. **前后对比**：同一场景，删掉 skill 跑一次，装上跑一次。行为差异在哪？没差异说明 skill 无效。
2. **压力测试**：给 agent 制造偷懒的机会（时间紧、任务简单、用户催），看它是否仍然遵守。会破的地方就是漏洞，写死它。
3. **安装校验**：

```bash
grep -rl "^name: cht-full-skill" ~/.codebuddy/skills/*/SKILL.md
```

能列出路径才算装好。列不出，说明 `name` 与目录名不一致，或 frontmatter 被破坏。

---

## 6. 常见失败

| 失败 | 症状 | 修法 |
|---|---|---|
| description 写成摘要 | 从不被触发 | 改成"何时用 + 触发词" |
| 全是形容词 | 无法执行 | 全部换成数字与动作 |
| 太长 | 加载后没人读完 | 拆到 references，主文件只留路由 |
| 写成了教程 | agent 读了不用 | 改成命令式检查清单 |
| 没有完成定义 | 不知道什么时候算做完 | 加可勾选清单 |
| 引用失效路径 | 执行时找不到文件 | 每次改动后跑漂移检查 |

---

## 7. 完成定义

- [ ] `name` = 目录名，frontmatter 完整
- [ ] description 含场景与触发词，能被人一眼判断"该不该用"
- [ ] 做了基线测试，记录了 agent 原本的失败方式
- [ ] 装上后同场景行为改变，且可复现
- [ ] 压力测试过，漏洞已堵
- [ ] 所有命令/路径已验证存在
- [ ] 安装校验命令能列出本 skill
