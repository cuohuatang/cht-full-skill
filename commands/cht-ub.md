# /cht-ub · 工程纪律（三段式 + 量化门）

> 受 Robert C. Martin（Uncle Bob）的 `ub-mode` 启发而作**原创重述**（ub-mode 未声明许可，本命令不复制其文件，仅吸收其纪律）。
> 完整纪律见 `references/18-engineering-discipline.md`。

## 什么时候用

- 用户要求"遵守工程纪律""量化门禁""攻击前提式排查""先减后加"
- 代码要进主干，但没标准判断"改到什么程度算干净"
- 多处修复都倒在同一道门上，越修越乱

## 一次调用做的事

1. **确认语言是否在门禁工具支持范围**（crapper/dryer/mutator 支持 Clojure/Java/Go/TS/Rust/Python）。
   - 在支持范围内 → 提示可装对应的 **0BSD** 工具跑三道门（CRAP<10 / 重复度<0.8 / 变异 0 存活）。
   - **不在范围内 → 只用行为纪律，不引入额外工具链**（守住"0 运行时依赖"）。
2. **套三段式顺序**：① Make it Work（最小可用）→ ② Make it Right（按门禁重构）→ ③ Practice（留痕 + 小步提交）。
3. 遇到"多处修复卡同一道门" → 用 **攻击前提**：把共享前提一句话写出，数清谁持不平衡，**先移除这个赋值**。

## 输出模板

```
纪律：三段式 / 量化门 / 攻击前提
① Work  ：<最小可用改动，已 TDD 红→绿>
② Right ：<过哪几道门；CRAP max=X(<10?) / 重复度=Y(<0.8?) / 存活变异=Z(=0?)>
③ Practice：<每步动作+理由已记录；提交 N 笔，每笔写清 why/what/prove>
```

## 红牌（违反即停）

- 把"做对"和"做出来"混一遍写 → 拆开，先 Work 再 Right
- 数字门没过却声称"重构完成" → 回去拆/补测
- 为了跑门禁给纯脚本项目塞重工具链 → 禁用，只用行为纪律

## 不重复造轮子

TDD、根因调试、评审、QA、提交纪律已有对应参考（03/04/05/06/10）。本命令只补 **量化门阈值** 与 **攻击前提** 两块，不替代它们。
