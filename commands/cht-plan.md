# /cht-plan — 拆解与三路审查

前置：`docs/cht/SPEC.md` 存在且用户已批准。没有就回去 `/cht-spec`。

## 执行

1. **定范围模式**（四档之一，写进计划头部）：扩张 / 选择性扩张 / 维持 / 收缩。**默认收缩。**
2. **定文件结构**：新增 / 修改 / **不动** 三段式。一起变化的东西放一起，按职责切不按层切。
3. **拆任务**：每个任务四要素齐全——
   `文件路径` + `接口签名（含错误行为）` + `验证命令或测试名` + `完成定义`。
   粒度：30–120 行改动，一次提交一次验证。超过 200 行就拆。
4. **工程审查**：数据流图 + 状态表 + 错误矩阵 + 测试矩阵 + 边界清单 + 迁移（`references/02-planning.md §4.1`）。
5. **设计审查**（有 UI 时）：七维度打分 0–10，AI 味排查，逐项改计划。
6. **产品审查**：写出一句"用户上线后会说的人话"；回答"只留一个功能留哪个"。
7. **风险与回滚**：风险表（概率/影响/对策）+ 回滚方式。
8. 落盘 `docs/cht/PLAN.md`（模板 `assets/templates/PLAN.md`），请用户批准后进 `/cht-build`。

## 禁止

- 任务写成"实现 X 功能""优化性能"（不可判定）
- 只画 happy path
- 在计划里混进实现代码

## 完成判据

- [ ] 范围模式已选定并写明砍了什么
- [ ] 文件结构含"不动"清单
- [ ] 每个任务四要素齐全
- [ ] 数据流/状态/错误/测试四张表在
- [ ] 有 UI 时七维度已打分
- [ ] 风险表 + 回滚方案
- [ ] 用户已说"开始"
