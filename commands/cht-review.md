# /cht-review — 代码评审

## 参数

| 参数 | 作用 |
|---|---|
| （无） | 评审当前分支相对主干的改动 |
| `--staged` | 只评审暂存区 |
| `--security` | 只做安全专项 |
| `--diff <base>..<head>` | 指定范围 |

## 执行

1. **看规模**：`git diff --stat`。超过 400 行，建议拆分评审并说明理由。
2. **逐文件读 diff**（不是读作者描述）：结构 → 核心逻辑 → 测试。
3. **按优先级查**：正确性（边界/异步/资源/幂等）→ 安全（注入/越权/密钥/外部输入）→ 数据（迁移/事务/并发）→ 性能（N+1/循环 await）。
4. **门禁完整性专查**：弱化断言、`.skip`、超时调大、快照无脑更新、吞异常、lint 禁用、覆盖率阈值下调。**每一项点名到人 + 原因 + 恢复时间。**
5. **输出分级发现**，每条带 `文件:行号`：
   ```
   [P0] path:42 — 问题一句话
        证据：<片段>  建议：<具体改法>
   ```
   机械问题直接标 `AUTO-FIXED` 并列出改了什么；需决策的标 `ASK` 并停下来问。
6. 落盘 `docs/cht/REVIEW.md`。

## 禁止

- "整体不错，建议优化性能"（无行号、无级别）
- 把风格偏好当 P0
- 沉默地全改（ASK 级必须问）

## 完成判据

- [ ] P0/P1 清零或有豁免记录
- [ ] 门禁降级全部点名
- [ ] ASK 项已获用户决策
- [ ] 自审清单（`references/05-review.md §5`）全勾
