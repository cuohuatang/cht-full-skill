# /cht-qa — QA 与验证

## 参数

| 参数 | 作用 |
|---|---|
| `<url \| 命令 \| 端点>` | 被测对象 |
| `--smoke` | 只跑上线前冒烟清单 |
| `--verify "<结论>"` | 只做完成前验证（证伪某句话） |

## 执行

1. **选环境路径**（`references/06-qa.md §2`）：
   网页→真实浏览器走关键路径 / API→真实请求含越权与幂等 / CLI→真实终端含错误参数 / 任务→手动触发含失败与重入 / Webhook→投递+重放+签名错误。
   **不用 mock 当 QA。**
2. **每个 bug 六要素**：复现序列 / 可重放证据（截图、请求、日志）/ 根因 / 修复 / 回归测试 / 复验结果。
3. **回归测试**：先跑成 RED，修完变 GREEN。没看到 RED 不算修好。
4. **探索清单**：输入侧（空/超长/特殊字符/重复提交/并发）、状态侧（深链接/刷新/限速/断网/空数据/海量数据）、权限侧（越权/过期 token）、恢复侧（重试/中断/回滚后读旧数据）。
5. **冒烟**（`--smoke`）：健康检查含版本 / 核心路径 / 真实写读 / trace id / 无新错误 / 无 404 / 移动端不破版。
6. 落盘 `docs/cht/QA-REPORT.md`（模板 `assets/templates/QA-REPORT.md`）。

## 完成前验证（说任何"完成"之前）

```
1. 识别：哪条命令能证明这句话
2. 执行：完整跑一遍（新鲜的）
3. 阅读：读完输出，看退出码，数失败
4. 对照：输出真的支持这句话吗
```

禁止措辞（除非刚跑过并贴了输出）："应该可以了""测试都过了""已修复""部署成功"。

## 输出

```
验证：<命令>
结果：<退出码> <x passed / y failed> <耗时>
说明：覆盖了什么，没覆盖什么
```
