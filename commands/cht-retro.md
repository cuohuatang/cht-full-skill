# /cht-retro — 复盘与记忆

## 执行

1. **收集素材**（不凭印象）：
   ```bash
   git log --oneline <上次复盘>..HEAD
   cat docs/cht/LEDGER.md        # 裁决与阻塞最多的地方就是问题所在
   cat docs/cht/REVIEW.md        # P0/P1 的分布反映系统性问题
   cat docs/cht/QA-REPORT.md
   ```
2. **四问**（每问 2–4 行，不写长）：

```
1. 做对了什么？（具体到动作，不写"沟通顺畅"）
2. 做错了什么？（具体到决策，不写"时间不够"）
3. 哪个假设错了？（最有价值的一栏）
4. 下次具体改什么？（一条可执行动作，不写"加强重视"）
```

3. **提炼 learnings**：从上面四问里提取可直接复用的判断，追加到 `docs/cht/LEARNINGS.md`：

```
[坑|约定|偏好|依赖|流程|环境] <一句可执行的判断>  (YYYY-MM-DD, 来源：<任务>)
```

4. **清理**：删过时条目，合并重复。**超过 30 条等于没有。**
5. 落盘 `docs/cht/RETRO.md`（模板 `assets/templates/RETRO.md`）。

## 判据

> 如果这四条别人看了不能照着做，复盘就是失败的。

反例：「需求理解不够充分，下次加强沟通。」
正例：「把'支持多语言'默认当成需求，实际只有中文场景。下次 SPEC 的非目标栏里，把没被明确要求的能力全部写进非目标。」

## 完成判据

- [ ] 四问填写，第 4 条是可执行动作
- [ ] 至少一条 learnings 已写入
- [ ] 过时 learnings 已清理
- [ ] 下个会话只需读 5 个文件就能接上（见 `references/10-memory.md §6`）
